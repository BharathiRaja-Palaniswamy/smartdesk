# M0: Bring the engine into SmartDesk

Status: **approved** (full LangChain; SQLite in M1; fix 8 left as data;
customer site stays in spaDesk).

## Goal

SmartDesk's repo runs the working engine (chat agent, booking, search,
phone line, owner reports, tracing, evals), with:

- **full LangChain**: one path for everything, built from LangChain and
  LangGraph parts, with no hand-built versions alongside,
- generic names (`smartdesk`, Front Desk) instead of spa-only ones,
- spaDesk's known customer-facing bugs fixed, each with a test,
- live debug events,
- the pre-push check running on every push,

and **every existing test still passing**. Still one business at a time,
named by settings; cells, SQLite and many businesses come in M1.

spaDesk itself is **not touched**: it stays live for its business until the
SmartDesk widget replaces it (M7). M0 copies; it does not move.

## Full LangChain: what replaces the hand-built parts

| Hand-built in spaDesk | In SmartDesk |
|---|---|
| `rag/` chunking, in-memory store, retriever, rerankers | dropped; `search/` is LangChain throughout |
| local ONNX embeddings (MiniLM) and reranker (cross-encoder); `onnxruntime`, `tokenizers`, `huggingface-hub`, `numpy`; `scripts/download_models.py` | `PineconeEmbeddings` and `PineconeRerank` (`langchain-pinecone`), hosted; the live default already; the in-memory store stays only as LangChain's `InMemoryVectorStore` for tests |
| `models/tools.py` `Tool` and `run_requests` | LangChain `StructuredTool`, bound with `bind_tools`, run with `tool.invoke` |
| gateway fallback | `.with_fallbacks()` |
| `models/structured.py` | `.with_structured_output(<Pydantic model>)` |
| `models/usage.py` | `usage_metadata` read by one callback that logs tokens, time and cost |
| job → model map (`profiles.py`) | kept as settings; models built with `init_chat_model` |

**Testing search (D21).** Tests use LangChain's `DeterministicFakeEmbedding`
and no reranker: they check the wiring (chunks, headers, namespaces, what is
stored and returned) quickly, offline and repeatably. Whether search finds
the right passage is a quality question, checked by the retrieval eval
(`evals/retrieval.py`, rebuilt on LangChain) against real Pinecone, run with
approval like the other evals. Chat and agent tests use LangChain's fake chat
models (`GenericFakeChatModel`) instead of the hand-built path spaDesk's
tests switched to.

Kept on purpose: the Front Desk turn is a **custom LangGraph graph**
(identify → agent → tools → the customer's yes → booking code), not the
prebuilt agent or `ToolNode`, because those run a requested tool at once;
ours must stop for the customer's yes before any booking change.

|---|---|---|
| package `spadesk` | `smartdesk` | the product |
| `agent/` | `frontdesk/` | the agent's role in every business |
| the agent's module | `frontdesk/agent.py` | named by its role; the assistant's own name is the business's setting |
| `lc/` | `search/` (retrieval) and `owner/` (owner graph) | named by job, not library |
| `SPADESK_*` settings | `SMARTDESK_*` | |

## No business in SmartDesk (D23–D25)

SmartDesk is the engine; a business is its data. So nothing in this repo
names a real business or holds its files:

- Code, prompts and pages are generic: "staff member", not "therapist"; "the
  business", not "the spa"; the assistant's name is a setting.
- The first business's document, bookings, golden set and bookings generator
  stay in spaDesk's repo; SmartDesk reads a business's files from paths in
  its settings (`SMARTDESK_DATA`, `SMARTDESK_REPORT_DATA`, `SMARTDESK_EVAL_SET`),
  which have no default.
- Tests run against a made-up test business (`tests/fixtures/`): the same
  kinds of services, packages, classes and staff, with neutral names, so
  every test keeps its meaning.
- When the first business is used with SmartDesk again (M2), its golden set
  follows the code: its agent target becomes `frontdesk`, and `therapist`
  becomes `staff_member`.

## Cleaning on the way over

Nothing is copied as-is: each file is read and cleaned as it moves.

| What | Rule |
|---|---|
| Dead code | functions, settings, routes and tests nobody uses are removed, not carried (checked with `vulture`) |
| Duplicates | one helper for one job; copies merged |
| Comments | kept as teaching comments, but rewritten where they describe spaDesk history ("hand-built", the assistant's old name, "the reference engine", week numbers) instead of what the code does now |
| Names | generic and by job (`frontdesk`, `search`, `owner`); no spa-only words (D24) |
| Settings | only settings the code reads; each with a one-line meaning; `SMARTDESK_` prefix |
| Dependencies | only what is imported; dropped: `onnxruntime`, `tokenizers`, `huggingface-hub`, `numpy`, `tiktoken` if unused after the move |
| Style | `ruff` for unused imports, undefined names and formatting; added to the pre-push check |
| Size | small files, one job each (project rule); any file over ~300 lines is looked at for a split |
| Never copied | `.env`, `storage/` (hand-offs and feedback contain test customers' details), `__pycache__`, local model files, spaDesk's course pages (`docs/week-*`) |
| Tests | tests of removed code removed; the rest renamed and kept; no test changed to pass without a reason written in the commit |

## Live debug events

Replaces spaDesk's after-the-turn debug notes (plan, section 7, "Debug view"):

- One event shape: who, kind (ai · tool · code · person), to whom, what,
  status, time in ms, redacted data, trace link.
- Each agent, tool and step declares its own kind; the hand-kept `KINDS`
  list goes.
- `GET /api/debug/stream` (server-sent events) for the signed-in owner only;
  off unless `SMARTDESK_DEBUG=true`; never for customers.
- Events never carry system prompts or secrets; personal details hidden.
- The widget's debug drawer and the onboarding panel use it later (M6, M7).

## Pre-push check

- `scripts/pre_push.sh`: run `ruff` and the tests; scan the changes for
  secrets; fail if `.env` or keys are staged.
- `.githooks/pre-push` calls it; `git config core.hooksPath .githooks`
  turns it on (documented in the README).
- The review items of `docs/checklists/PRE-PUSH.md` stay in the commit message.
